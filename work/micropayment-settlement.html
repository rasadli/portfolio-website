Ongoing senior design project, 2026–2027

AI-Optimized AZN Micropayment Batching and Settlement

When a payment is very small, the cost of settling it alone can matter more than the payment. Batching fixes that and creates a new problem: every payment waits for its batch.

My graduation project at ADA University designs an adaptive, machine-learning-based batching system for micropayment settlement in distributed environments, with a focus on payments in Azerbaijani manat (AZN). It evaluates transaction throughput, confirmation latency, settlement overhead and fault tolerance against fixed batching strategies.

Concepts the project works with

Micropayment processing
Handling large numbers of very low-value payments, where per-transaction costs weigh heavily on each one.
Fixed batching
Settling on a set schedule or at a set size. It is simple and predictable, but it ignores how traffic actually arrives.
Adaptive batching
Changing when a batch closes in response to current conditions, such as load or how long the oldest payment has waited.
Settlement overhead
The cost of finalizing payments. Grouping them spreads that cost across more payments.
Confirmation latency
How long a payer or merchant waits for a payment to be confirmed. Bigger batches tend to increase it.
Throughput
How many payments the system can process in a given time, which sets the upper limit on useful batching.
Fault tolerance
A batch must not lose or duplicate payments if something fails partway through settlement.
Simulation and evaluation
Testing strategies against the same simulated workloads, so that differences can be attributed to the strategy.
Machine-learning-based batching
Using a learned model to make batching decisions, then testing it against fixed strategies.

Status

The project is in progress. It has no published results or papers yet, so this page describes the question and not an answer.
